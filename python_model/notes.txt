Multiplying any two d-degree polynomials is O(d^2) --> naively using distributive property for multiplication

Polynomial Representation: (d+1) points uniquely define a degree d polynomial
    Iow: For every set of d+1 points, there is a unique polynomial that passes through all of them

Polynomial Representation:
P(x) = p0 + p1*x + p2*x^2 + p3*x^3 + pd * x^d

Coefficient Representation: P(x) = [p0,p1,p2,p3,..,pd]

Value Representation: P(x) = {(x0,P(x0)),(x1,P(x1)),(x2,P(x2)),(x3,P(x3)),...,(xd,P(xd))}

Any discrete time (DT) signal can be expressed as summation of sinusoids
So, in the time-domain, Cosine and Sine serve as the ORTHOGONAL basis functions of any DT signal
    IoW, because they are orthogonal, you can project any time-domain signal onto them
    Also remember that Cosine + Sine pairs can be expressed as complex exponentials

So basically, we have that: discrete-time signal (time-domain) --> summation of sinusoids (time-domain also)
    The coefficients of those sinusoids, however, live in the frequency domain

The frequency domain is defined by those two basis functions.
In particular, the coefficients of the sinusoids resulting from the decomposition are the FD representation

Discrete Fourier Transform (DFT): an algorithm that decomposes a DT signal in the time-domain 
    into a frequency-domain representation


DFT: time domain --> frequency domain


N: no of points in FFT implementation
M: no of points in input stream
P_total: pipeline delay (corresponds to the number of pipeline registers)
    P_total = log2(N)   if we are using output registering
    P_total = log2(N)-1 if we are not using output registering
C_i: num of cycles until ith output, where cycle index i starts at 1

C_1 = C_first = 1 + (N-1) + P_total
    the 1 is for the initial cycle (input arrival)
C_M = C_last = C_first + (M-1) = M + N + P_total - 1
Important note: 
    - cycle indexing starts at 1
    - those formulas (cycle counts) are relative to the arrival of the first input. Previous cycles (e.g. cycles consumed for reset) are not accounted for


N is almost always a power of 2
If M is not a power of 2, approximate it to nearest larger power of 2 and zero-pad (add zeros to the end of the stream)

Observations from this manual trace:
    - each stage goes through a cycle of length delay_len*2
    - each stage spends the 1st half of the cycle Fill/Flush mode, and 2nd half in Compute mode
        Fill/Flush Mode: (note: the name itself is a bit misleading, as the fill/flush happens also in Compute mode, but is used here to designate the mode's name)
            Flush: an already buffered output at head of the buffer queue is flushed to the next stage (or final output if in final stage)
            Fill: an incoming input is buffered (filling the buffer)
            BF unit is OFF
        Compute/Butterfly Mode:
            BF unit is ON and produces outputs A and B according to the DIF equations
            Flush: output A from the BF is flushed to the next stage (or final output if in final stage)
            Fill: output B from the BF is buffered (filling the buffer)
    
    
    - each stage makes exactly N/2 computations






About the Fixed Point part:


Why exactly +1 bit per stage?
    Because each stage performs one butterfly, and a butterfly contains:
        one addition    --> increase magnitude
        one subtraction --> increase magnitude
        one twiddle multiplication --> doesn’t increase magnitude (|W| = 1),

Grow integer bits only when needed to avoid overflow.
(Usually +1 per stage internally.)


Grow fractional bits only when you need more SQNR.
(+6 dB per bit.)

Do NOT grow both unless you have a reason.
This is why FFT cores typically do:

internal integer bit‑growth (to avoid overflow)

fixed fractional width (to control SQNR)
